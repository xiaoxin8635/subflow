# SubFlow 后续开发路线图（ROADMAP）

> 更新时间：2026-10-10。基于 MVP（模块 ①-⑤ 已完成）的现状，按「上线前必做 → 上线后增强 → 增长期扩展」三期排布。
> 每期标注预估工作量（按每天可投入开发计算）。原则：**先堵住会翻车的洞，再做增长性功能**。

## 现状盘点

已完成：注册登录（短信验证码）→ 上传（≤500MB）→ ASR 转写（qwen3-asr-flash）→ LLM 润色 + 关键词高亮 → 字幕编辑器 → ASS 烧录导出 MP4 → 额度扣减 → 激活码收款 → 管理后台 → 购买页 → Docker 部署产物。

当前架构瓶颈（高并发下按倒下顺序）：

1. **带宽**：视频经服务器中转，3-5Mbps 带宽下 500MB 上传 15-25 分钟，10 个并发用户就把带宽占满
2. **进程内任务**：转写/导出为 fire-and-forget，容器重启丢任务；无并发上限，FFmpeg 烧录是 CPU 密集型，2核4G 同时烧 3-4 个视频就打满
3. **单机单点**：应用 + 数据库 + 文件全部在一台机器，无法水平扩展

## 第一期：上线前必做（P0，预估 4-6 天）

### 1.1 SRT 字幕导出 ⚠️ 落地页已宣传但未实现
- **需求**：导出时同时生成 SRT 文件（`/api/exports/[id]/download?type=srt` 或独立按钮），编辑器页提供单独的「下载 SRT」入口
- **动机**：落地页承诺「MP4 + SRT」，兑现宣传；SRT 是剪映/PR 二次剪辑刚需
- **验收**：下载的 SRT 可被剪映正常导入，时间轴与编辑器一致

### 1.2 法务页面 /privacy /terms
- **需求**：隐私协议（视频数据用途、存储期限、删除权利）+ 用户协议；页脚挂链接与 ICP 备案号占位
- **动机**：ICP 备案审核要求；处理用户视频必须有隐私声明
- **验收**：两页可访问，内容覆盖数据收集/使用/存储/删除条款

### 1.3 API 限流与防刷加固
- **需求**：按 IP + 手机号限流（发码 1 条/分钟、登录 5 次/小时、上传 5 个/小时、兑换 10 次/小时、导出 10 次/小时）；上传文件魔数校验（防改后缀）；超出返回 429
- **动机**：现仅发码有冷却；激活码可被脚本暴力穷举，上传接口可被刷爆磁盘与 ASR 费用
- **验收**：压测脚本触发限流返回 429；伪造后缀文件被拒

### 1.4 大文件分片上传 + 断点续传
- **需求**：浏览器端分片（如 5MB/片）并行上传，服务端合并；中断后可续传
- **动机**：500MB 直传成功率低、失败从头再来，是用户流失第一现场
- **验收**：模拟中断后重试，从断点继续；上传速度感知提升

### 1.5 落地页宣传修正
- **需求**：「Paraformer」改为实际使用的 qwen3-asr-flash 描述（或统一写「阿里云百炼语音识别」）；价格区文案与 Plan 表核对
- **动机**：宣传与实现一致性（已发现两处不符）
- **验收**：全站无与实现不符的宣传语

### 1.6 项目列表分页 + 额度不足提示优化
- **需求**：工作台项目列表分页（20/页）；402 场景给出明确引导（跳转 /pricing）
- **动机**：用户项目增多后全量拉取变慢；付费转化路径顺畅

## 第二期：上线后增强（P1，预估 8-12 天）

### 2.1 Redis 任务队列（BullMQ）——高并发第一步
- **需求**：转写/导出任务进 Redis 队列，Worker 进程消费；任务状态持久化（重启可恢复）；并发上限可配（如 FFmpeg 同时 2 个）；失败自动重试 + 死信告警；支持优先级（付费用户优先）
- **动机**：解决「重启丢任务 + CPU 打满 + 无公平调度」三大问题
- **验收**：kill 容器重启后进行中任务可恢复或标记失败可重试；并发烧录数不超上限

### 2.2 OSS 直传 + CDN（高并发第二步，消灭带宽瓶颈）
- **需求**：前端拿 STS 临时凭证直传阿里云 OSS → 回调触发转写；成片写 OSS 并走 CDN 下载；`storage.ts` 抽象切换实现（已预留 `publicUrlFor`）
- **动机**：视频流量不再经过应用服务器，单机带宽限制解除；下载速度质变
- **验收**：上传/下载流量不占服务器带宽；PUBLIC_ASSET_BASE_URL 配 OSS 外链供 DashScope 拉取

### 2.3 任务完成通知
- **需求**：转写/导出完成后浏览器通知 + 站内信；（可选）短信/微信服务号通知
- **动机**：处理需等待，用户会关页面，回来发现早完成了

### 2.4 多格式导出
- **需求**：SRT / ASS / VTT 一键下载（纯文本生成，零额外算力）；导出记录页
- **动机**：覆盖专业剪辑用户

### 2.5 批量处理
- **需求**：一次选多个视频排队上传转写；队列位置可视化（第 N 位）
- **动机**：高频创作者核心痛点，也是付费点

### 2.6 可观测性
- **需求**：结构化日志 + 错误上报（Sentry 免费档）；任务失败/额度异常的告警（邮件或钉钉/飞书 webhook）；管理后台加「失败任务」页
- **动机**：出问题能第一时间知道，而不是用户投诉才发现

### 2.7 CI/CD
- **需求**：GitHub Actions：push → lint + build + E2E（自托管 runner 或服务器拉取）→ 自动部署
- **动机**：摆脱手工 SSH 部署，降低发版事故

## 第三期：增长期扩展（P2，按需启动）

### 功能多样化
| 需求 | 说明 | 备注 |
| --- | --- | --- |
| 字幕翻译 | 千问翻译生成中英双语字幕，可单独导出或烧录双语 | 出海创作者刚需，强付费点 |
| OCR 硬字幕提取 | 有画面字幕无人声的视频，用 OCR 提取已有字幕 | 扩大可处理视频范围 |
| 音频直传 | 支持 MP3/WAV/M4A（播客、课程转字幕） | 复用现有转写链路，成本低 |
| 自定义样式保存 | 用户调好的字体/颜色/位置存为个人模板 | 提升粘性 |
| 时间轴批量调整 | 全局偏移/缩放，对齐口型 | 高频编辑需求 |
| 片段导出 | 选时间段裁剪导出 | 差异化功能 |
| 邀请裂变 | 邀请新用户双方得时长 | 低成本获客 |
| 加油包 | 非订阅的一次性时长包（如 ¥9.9/60min） | 低门槛付费点 |

### 商业化升级
- **微信支付/支付宝当面付**：办下商户资质后替换激活码主路径（激活码保留作为线下渠道）；需要对账系统与回调幂等
- **订阅自动续费**：微信支付代扣，减少月付流失

### 高并发第三步：水平扩展（日活过千再考虑）
- 应用无状态化（文件全在 OSS 后即可）→ 多实例 + SLB 负载均衡
- PostgreSQL：连接池（PgBouncer）、读写分离、按月分区 CreditLedger
- Redis 缓存热点数据（套餐、样式、会话）
- 多地域 CDN 加速

## 建议节奏

```
本周          ：第一期 P0（4-6 天）→ 具备正式上线条件
上线后 2 周    ：2.1 任务队列 → 2.2 OSS 直传（高并发两大件）
之后按数据决定 ：通知/多格式/批量 → 翻译/OCR/微信支付
```

> 优先级判断依据：P0 是「不上线会翻车/违反宣传」；2.1/2.2 是「并发上来必挂」；P2 是「增长后的锦上添花」。
